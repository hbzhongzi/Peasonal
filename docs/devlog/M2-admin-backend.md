# M2 · 管理后台与用户权限

本阶段核心目标：让站长能管理用户/权限/评论，让普通用户能管理自己的博客内容；同时把「后台管理」与「个人博客编辑界面」彻底分离，并按用户隔离数据。

## 背景

M2 不是单纯的后台 CRUD，而是一套权限与界面分层：

- `/admin`：纯管理后台，仅 `is_admin=1` 可进。负责用户管理（含权限升降）、评论清理。
- `/studio`：我的博客工作台，仅 `can_publish=1` 可进。负责写文章、管媒体、维护个人资料。
- 普通注册用户默认 `can_publish=1`（注册即作者）、`can_upload=0`（上传为管理员授予特权）、`is_admin=0`（M2 补充八，2026-09-30 反转 v1.6 默认值）。
- 数据按 `author_id` 行级隔离：作者只能看见/改/删自己的内容，管理员可看全站。

## 已实现能力

- 用户注册、登录、JWT 双 token（access 15min + refresh 7d HttpOnly Cookie）、argon2id。
- 三级权限中间件：`RequireAdmin`、`RequirePublish`、`RequireUpload`。
- 401 自动续期：前端 `coreFetch` 捕获 401 后用 refresh cookie 换新的 access token，并发去重后重试原请求。
- 后台页面：文章表格（草稿/已发布筛选、发布/转草稿、删除）、编辑器（标题/slug/摘要/标签/封面/评论开关 + Markdown 实时预览）、媒体库（上传/列表/删除/复制链接）、评论管理（按 slug 查全部、隐藏/恢复/删除）。
- 前台用户模块：公开 `/blog/:publicID` 用户主页、文章署名、用户菜单、个人资料 `/studio/profile`。
- 前台与后台断链：前台任何位置（导航、用户菜单、文章详情页、登录后分流）都不出现指向 `/admin` 或 `/studio` 的入口；后台/工作台只能通过直接输入 URL 访问。

## M2 补充（四）：数据按用户隔离 + 个人资料数据化（2026-09-29）

### 背景

用户反馈：**「不同用户登录看到的个人隐私应该不一样」**。核心痛点：文章、媒体、个人资料都没有按用户隔离，登录者能看到/操作别人的内容。

### 实现

- 数据库
  - 迁移 `00024`：`media` 表新增 `author_id`（`0` 表示历史遗留，仅管理员可管）。
  - 迁移 `00025`：`users` 表新增 `bio`、`avatar_url`、`github`。
- 后端
  - 新增 `service.Actor`：统一封装 `AuthorFilter()`（查询时按作者过滤）与 `CanTouch(ownerID)`（写操作时判断能否触碰）。
  - 文章/媒体/评论相关查询全部改走 `Actor`，跨用户改删 → 403「只能操作自己创建的内容」。
  - 新增 `PATCH /admin/me`：本人改自己资料，ID 只从 token 取，不接受路径参数。
  - 新增匿名 `GET /site/profile`：返回站长公开资料（id 最小的管理员），不含邮箱。
  - 评论管理由 `RequirePublish` 改为 `RequireAdmin`，入口从 `/studio/comments` 挪到 `/admin/comments`。
- 前端
  - 新增 `/studio/profile` 个人资料页。
  - 新增 `features/site/useSiteProfile.ts`。
  - `Hero`、侧边栏、关于页、页脚、`StudioLayout` 顶栏全部改由接口驱动；`config/site.ts` 退化为兜底默认值。

### 验证

- `go build ./...` + `npm run build`（118 模块）通过。
- curl 实测 9 项权限与隔离断言全过。

### 方案偏离

- 个人身份信息从 `config/site.ts` 硬编码迁移到数据库 + 接口驱动。
- 技术方案升 **v1.8**。
